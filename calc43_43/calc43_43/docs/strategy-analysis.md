# calc43_43 项目"五看三定"战略分析

> 华为"五看三定"：通过看行业/趋势、市场/客户、竞争、自己、机会洞察战略机会点，
> 再定战略控制点、定目标、定策略，形成可落地的战略规划。

## 一、五看

### 1. 看行业/趋势
- 开源已成为全球软件产业的主流协作方式，GitHub 上托管的开源项目数以亿计，"人人参与开源"是明确趋势。
- Python 常年位居 TIOBE / PYPL 语言排行榜前三，是学习编程的首选语言，教学类小工具需求长期存在。
- AI 辅助编程兴起后，基础工具的门槛进一步降低，"小而美"的工具型项目更容易获得关注和贡献。

### 2. 看市场/客户
本项目的目标用户是：
- **初学者**：刚学 Python，需要一个能看懂、能改、能测试的小项目作为练手对象。
- **学生群体**：课程作业、实验报告中需要展示完整工程实践（文档、测试、许可证）的参考项目。
- **命令行爱好者**：喜欢轻量、无依赖的终端工具。

痛点：网上计算器代码质量参差不齐——多数没有测试、没有许可证、没有文档，不敢放心引用。本项目恰好补齐这一环。

### 3. 看竞争
| 竞品 | 优势 | 劣势 | 本项目差异化 |
|---|---|---|---|
| 网上随手搜到的计算器代码 | 随手可得 | 无许可证、无测试、代码质量差 | 有完整文档与测试，可直接放心使用 |
| Python 自带 eval 直接计算 | 零成本 | 有注入风险 | 输入过滤，安全可靠 |
| 大型开源项目（如 SymPy） | 功能强大 | 依赖重、源码复杂 | 零依赖、单文件、易读易改 |

### 4. 看自己
- **技术能力**：掌握 Python 基础语法、Git 分支管理与 GitHub 协作流程，能独立完成开发与测试。
- **资源条件**：项目零依赖、零成本维护，个人精力即可支撑。
- **短板**：功能目前较单一，图形界面、历史记录等高级功能尚待开发。

### 5. 看机会
- **教学场景空缺**：课程考核/实训普遍要求"许可证 + README + 分支管理 + Issue 协作"全流程，一个规范的小项目样板本身就是稀缺资源。
- **差异化定位**：市面上"功能最全"的计算器很多，"最适合学习工程规范"的计算器很少——这是本项目的机会点。

## 二、三定

### 1. 定战略控制点
**"工程规范性 + 易读性"**——这是竞品难以快速模仿、又能持续积累口碑的控制点。
具体抓手：完善的文档体系（README/CONTRIBUTING/CHANGELOG）、100% 通过率的单元测试、清晰的分支管理记录。

### 2. 定目标（可量化）
| 阶段 | 时间 | 目标 |
|---|---|---|
| 近期 | 本学期末 | 仓库 star ≥ 10，Issue 讨论 ≥ 5 条，完成 1 次合并冲突的解决演示 |
| 中期 | 半年内 | 发布 v2.0（支持历史记录、图形界面），star ≥ 50 |
| 远期 | 一年内 | 进入校园课程推荐项目列表，贡献者 ≥ 3 人 |

### 3. 定策略
- **产品策略**：保持零依赖、单文件易读的核心特性，每次迭代必须附带测试与 CHANGELOG 更新。
- **协作策略**：用 GitHub Flow 管理分支；Issue 先行——所有新功能先开 Issue 讨论再开发。
- **推广策略**：在课程群、知乎/CSDN 写"如何做一个规范的迷你开源项目"系列文章引流；邀请同学互提 Issue 形成真实协作记录。
- **迭代策略**：v1.x 打磨 CLI 体验 → v2.0 增加 tkinter 图形界面 → v3.0 探索打包发布到 PyPI。

## 三、结论
calc43_43 的机会不在于"计算功能"，而在于"规范的工程实践样板"。
以工程规范性为战略控制点，以教学和初学者为主要客户，通过内容分享与真实协作逐步积累社区，是一条投入小、可持续的落地路径。
